# 审视之眼 Pro (Vel'Koz) — 软件详细介绍

> 当前版本：V1.5.0 | 技术栈：Python + Streamlit | 用途：视觉质检验收工具

---

## 1. 软件定位

**审视之眼 Pro** 是一款基于 **Streamlit** 构建的桌面级**视觉质检验收工具**，用于审核标注数据（图片+文本）。

核心流程：**加载文件夹 → 逐组查看图片 → 判定合格/不合格 → 导出结果**

英文代号 **Vel'Koz**（虚空之眼），项目名取自"审视"之意。采用内嵌 Python embeddable 绿色版打包，用户解压后双击 `启动.bat` 即可运行，无需安装 Python 或任何依赖。

## 4. 架构设计

### 4.1 Mixin 多继承架构

V1.3.5 将原始 3,034 行的 `app.py` 拆分为 9 个模块，采用 Mixin 多继承组合：

```python
class AcceptanceApp(DataMixin, SettingsMixin, ExportMixin, ZoneAMixin, ZoneBMixin, ZoneCMixin):
    def __init__(self): ...
    def run(self): ...
```

- `app.py` 只负责**初始化 session_state** 和 **run() 路由**
- 各 Mixin 之间**无循环依赖**，MRO 顺序正确
- 方法总数：61 个（重构前后零行为差异）

### 4.2 三栏 UI 布局

```
┌─────────────────┬──────────────────────┬─────────────────┐
│     A 区 (左)     │      B 区 (中)        │     C 区 (右)     │
│                 │                      │                 │
│  状态统计指标     │   冷启动动画           │  👤 用户名 + ID   │
│  (6格 metric)   │   (未加载时)           │  📂 打开文件夹    │
│                 │                      │                 │
│  筛选按钮(6格)   │   四宫格图片展示        │  📷 错误截图(≤3张) │
│  分页列表        │   / 单图对比视图       │                 │

│                 │                      │  L1 / L2 分类    │
```

### 4.3 数据流

```
用户输入任务根目录
    ↓
scan_files_from_disk() — 按 scan_rules.json 扫描嵌套目录
    ↓  (每个N位数字文件夹 = 一组数据)
    ↓  匹配图片后缀(_1/_2/_3/_result) + 文本后缀(_ZH/_EN)
    ↓  提取标注员姓名(从路径段智能识别中文)
    ↓
生成 data_groups 列表:
  [{id, root, images[], originals[], txt_zh, txt_en, user_name, batch?}]
    ↓
A区展示列表 → B区展示图片 → C区操作判定
    ↓
save_to_disk() → 写入 CSV 文件
    ↓
导出: 合格数据复制 / 不合格归集 / Excel带图报表
```

## 5. 各模块职责详解

### 5.1 app.py（主入口，224行）

**职责**：初始化 session_state + run() 路由

**关键逻辑**：
- `__init__()`: 初始化 ~30 个 session_state 变量（布局、视图、标签、抽检模式等）
- `run()`: 设置页面配置 → 注入 CSS/JS → 创建三栏 → 根据状态路由到不同渲染路径

**路由逻辑**：
```
current_group 存在？
  ├─ Yes → A区(列表+导出+AI+设置+分类) + B区(图片/完成面板) + C区(控制面板)
  └─ No  → B区(冷启动动画+数据源加载+更多设置)
```

### 5.2 data_mixin.py（数据层，595行）

**职责**：CSV 读写、导航、保存、抽检

**核心方法**：

| 方法 | 作用 | 关键实现 |
|---|---|---|
| `_get_df()` | 读取 CSV 并缓存到 session_state | UTF-8-sig 编码，GBK 降级，3次重试 |
| `_save_df()` | 原子写入 CSV | `.tmp` → `fsync` → `os.replace`，5次重试 |
| `save_to_disk()` | 保存单条质检记录 | 更新/插入行，保存截图证据，同步ZH/EN文本 |
| `get_csv_filename()` | 生成 CSV 路径 | `{root_path}/_质检记录/{operator}/{prefix}_验收记录.csv` |
| `get_record_status_map()` | 获取所有 ID 的质检状态 | 从 CSV 构建 {ID: 结果} 字典 |
| `_get_filtered_ids()` | 按筛选条件过滤 ID | 支持：全部/未检/合格/修改后合格/不合格/待定 |
| `go_to_previous/next_group()` | 上/下一条导航 | 带 0.3s 防抖 + 预加载下 5 张图 |
| `sync_state_from_history()` | 从 CSV 恢复历史状态 | 同步 L1/L2/结果/备注/标签 |
| `reset_task_state()` | 重置所有任务状态 | 清除 ~20 类前缀的 session_state 键 |
| `start_sampling_acceptance()` | 启动抽检验收 | 随机采样 N% 数据 |
| `_handle_scanning()` | 处理扫描状态 | 扫描文件夹 → 可选标注员确认 → 设置 data_groups |

### 5.3 settings_mixin.py（设置层，637行）

### 5.5 zone_a.py（A区，179行）

**职责**：状态统计 + 筛选 + 分页列表

**渲染内容**：
- 6 个 metric 卡片（合格/修改后合格/不合格/未检/待定/合格率）

### 5.6 zone_b.py（B区，454行）

**职责**：冷启动动画、确认面板、图片展示、完成面板

**四种渲染模式**：

1. **冷启动动画** (`render_cold_start_animation`)：呼吸之眼 + 脉冲环 + 淡入标题
2. **标注员确认面板** (`render_confirm_panel`)：多标注员场景下的名称确认+纳入筛选
3. **图片展示** (`render_b_image_area`)：四宫格/单图对比，双击打开系统查看器
4. **完成面板** (`render_completion_panel`)：全检完成后的统计汇总+导出入口

**图片展示模式**：
- 四宫格：2×2 网格，每张图下方显示分辨率 + 📂 打开按钮
- 单图对比：顶部按钮切换，大图展示

**文本编辑区**：ZH（中文指令）+ EN（英文指令）双列文本框

**AI 质检结果**：读取 `final_report.csv`，按 ID 匹配显示 AI 质检通过/未通过 + 拒绝原因分析

### 5.7 zone_c.py（C区，325行）

**职责**：控制面板（信息、截图、导航、分类、状态、备注、标签）

**从上到下布局**：
1. 数据信息（👤姓名 + 🆔ID + 📂打开文件夹 + 🖼️打开原图）
2. 错误截图（Ctrl+V 粘贴，最多 3 张）
3. 上一条 / 下一条 导航按钮
4. L1 / L2 分类 pills
5. 最终结果按钮（2×2 网格：合格/不合格/修改后合格/待定）
6. 备注文本框 + 保存/提交表单
7. 快捷标签 pills
8. 标签管理（折叠面板）

**表单按钮**：
- 💾 仅保存
- ✅ 快捷合格 (X)
- 🔄 修改合格 (V)
- 🚀 提交并下一条（空格）

**提交逻辑**：
- 校验必填字段（L1/L2 + 结果）
- 调用 `save_to_disk()` 保存
- 保存成功后跳转下一条（或筛选列表首条/全量完成面板）

### 5.8 utils.py（纯工具，255行）

**职责**：不依赖 Streamlit 的纯函数

**关键功能**：

### 5.9 disk_io.py（磁盘IO，261行）

**职责**：带 Streamlit 缓存的磁盘操作

**关键函数**：

### 5.10 export_utils.py（纯计算，182行）

**职责**：导出相关的纯计算逻辑（无 UI）

### 5.11 css_styles.py（CSS/JS，139行）

**职责**：全局样式和状态按钮脚本

- 状态按钮颜色（合格=绿、不合格=红、修改后合格=蓝、待定=黄）

### 5.12 easter_eggs.py（彩蛋系统，117行）

**职责**：维克兹风格的 toast 台词触发

**触发条件**：
- 首次加载数据："我看到了……所有数据。"
- 首次判定不合格："知识，通过解构获取。"
- 连续不合格≥3次："有序的混乱……数据需要更多审视。"
- 连续合格≥5次："你的标注模式……可以预测。质量稳定。"
- 全检完成："分析完毕。批次已全部审视。"
- 截图粘贴："检测到异常。已记录。"
- 导出报告："知识，已封存。报告已导出。"
- 累计50次判定："集中你的注意力。疲劳会影响判断。"
- 撤销判定："重新校准中……"

所有触发带 30 秒冷却时间，部分为一次性触发。

## 6. 配置文件详解

### 6.1 scan_rules.json（扫描规则）

```json
{
  "folder_digit_length": 8,         // 数据文件夹名位数（如 17030003）
  "image_slots": [                  // 图片槽位（按顺序匹配）
    {"stem_suffixes": [""]},         //   槽位1: 原图 {id}.jpg
    {"stem_suffixes": ["_result"]},  //   槽位2: 结果图 {id}_result.jpg
    {"stem_suffixes": ["_1"]},       //   槽位3: 图1 {id}_1.jpg（可选）
    {"stem_suffixes": ["_2"]},       //   槽位4: 图2 {id}_2.jpg（可选）
    {"stem_suffixes": ["_3"]}        //   槽位5: 图3 {id}_3.jpg（可选）
  ],
  "text_slots": [                   // 文本槽位
    {"suffixes": ["_ZH", "_CH"]},   //   槽位1: 中文指令 *_ZH.txt 或 *_CH.txt
    {"suffixes": ["_EN"]}           //   槽位2: 英文指令 *_EN.txt
  ]
}
```

**注意**：每个槽位有多个 `stem_suffixes` 时，按顺序尝试匹配，命中第一个即停止。

### 6.2 categories_config.json（分类配置）

```json
{
  "L1": ["空间编辑", "人物/物体一致性"],          // 一级分类列表
  "L2": {                                         // 二级分类映射
    "空间编辑": ["位置改变", "位置推理", "位置标注"],
    "人物/物体一致性": ["人物一致性", "物体一致性"]
  }
}
```

可在 UI 的"分类管理"面板中增删改。

### 6.3 config/settings.json（用户设置）

```json
{
  "layout_width": 54,           // B区横向占比（%）
  "layout_height": 63,          // B区纵向占比（%）

  "root_path": "",              // 任务根目录

  "operator_name": "",          // 操作员姓名
  "task_type": "新标",          // "新标" 或 "返修"

}
```

### 6.4 config/tags.json（标签库）

```json
{
  "tags": ["标签1", "标签2", ...],      // 全部标签
  "frequent": ["常用1", "常用2", ...]   // 常用标签（≤5个）
}
```

```

├── _质检记录/
│   ├── {操作员}/
│   │   └── {标签}_{操作员}_{日期}_验收记录.csv    ← 质检记录
│   └── {标签}_{操作员}_{日期}_验收记录.xlsx        ← Excel报表
├── _00_Evidence_新标/                              ← 新标截图证据
│   └── {id}_{timestamp}_{i}.png
├── _00_Evidence_返修/                              ← 返修截图证据
│   └── {id}_{timestamp}_{i}.png
└── {标注员姓名}/
    └── {8位数字文件夹}/                            ← 每组数据
        ├── {id}.jpg                                ← 原图
        ├── {id}_1.jpg                              ← 图片槽位1（可选）
        ├── {id}_result.jpg                         ← 结果图
        ├── {id}_ZH.txt                             ← 中文指令（可选）
        └── {id}_EN.txt                             ← 英文指令（可选）
```

**CSV 列名**：姓名、图片ID、一级、二级、结果、备注、标签、错误截图、质检时间、路径

## 9. 已知问题与注意事项

### 9.1 快捷键脆弱性
快捷键通过 JavaScript `innerText.includes()` 文本匹配定位按钮（`settings_mixin.py:132`）。按钮文案变动（如"提交并下一条"改为其他文案）会导致对应快捷键失效。

### 9.2 Windows 文件锁
CSV 写入使用 `.tmp` → `fsync` → `os.replace` 原子写入 + 5 次重试（300-1500ms 间隔），适配 Windows NTFS 句柄释放延迟和杀毒软件异步扫描。

### 9.3 图片缓存策略
- LRU 缓存：100 张原图（`_load_and_rotate`）
- 显示缓存：50 条 / 100MB 上限（`get_display_image_bytes`）
- 预加载：滑动窗口预取下 5 张图

### 9.4 Streamlit fragment 行为
曾尝试 `@st.fragment` 局部刷新，后因重跑范围不可控（有时 fragment 重跑，有时全页重跑），改为全页重跑 + 图片缓存 + CSS 固定容器高度。

### 9.5 死代码
`_fsync_path` 方法（`data_mixin.py:142-156`）定义但从未调用，因 Windows 文件锁 bug 被弃用，当前 `_save_df` 使用同句柄 fsync 方案。

# v1.24.8 报告 — 图片查看器色彩管理 + 缓存自动刷新

- 日期：2026-11-26
- 分支：`1.24`
- 版本：`1.24.8`
- 基线：`v1.24.7`（`9d6cd6d`）

## 一、问题现象

- 同一场景的两张图：`40000009_2.jpg` 和 `40000009_result.jpg`。
- 市面查看器（Windows 照片等）看两张色调一致；本查看器看色调不一致。
- 查看器截图里的 `40000009_2.jpg` 显示黑色裤子，但磁盘上的当前文件是黄绿色裤子。

## 二、原因分析

### 1. 两张图的 ICC 色彩空间不同（色调不一致）

读取文件内嵌 ICC：

| 文件 | ICC 色彩空间 |
| --- | --- |
| `40000009_2.jpg` | Adobe RGB (1998) |
| `40000009_result.jpg` | sRGB IEC61966-2.1 |

- Windows 照片、Chrome 等会做色彩管理，把图片转换到显示器空间。
- 查看器原来直接把 `QImageReader` 的结果转 `QPixmap` 显示，没有统一转到 sRGB；悬浮窗更是 `PIL → PNG` 保存时丢掉了 ICC。
- 结果：Adobe RGB 那张偏暗/偏饱和，sRGB 那张正常，肉眼看起来就是两张色调不一致。

像素验证（裤子位置）：

- 原始值：`(144, 141, 0)`
- 转 sRGB：`(147, 142, 0)`
- 整图均值和局部颜色也有可感知差异。

### 2. 缓存没有文件签名校验（显示旧图）

- 查看器缓存原来只用路径作为 key；`request()` 命中缓存就直接返回，不检查 `mtime / 大小`。
- 如果查看器打开期间图片被外部工具更新，缓存不会失效，仍然显示旧版本。
- 用当前代码新建查看器进程实测：`2.jpg` 正常显示黄绿色裤子；你截图里的黑裤子是旧版本缓存。
- 悬浮窗缓存同样只按路径，未做失效检查。

## 三、修复内容

### 1. 统一转 sRGB

- `image_viewer/image_loader.py`
  - 新增 `_to_srgb()`：带 ICC 且不是 sRGB 的图片，解码后转为 sRGB。
  - 预览图和全分辨率图都转换；同步加载也转换。
- `viewer/image_dock.py`
  - PIL 读取后用 `ImageCms.profileToProfile` 转 sRGB，再生成 QPixmap。
  - 同时改用 `ImageOps.exif_transpose` 修正 EXIF 方向（比原手写旋转更完整）。
- `disk_io.py`
  - 主界面显示图生成时也转 sRGB，保证主界面、悬浮窗、独立查看器颜色一致。
- `image_cache.py`
  - `CACHE_VERSION` 从 1 升到 2，旧显示缓存自动失效并重建，避免继续使用转换前的旧图。

### 2. 缓存按文件签名失效

- `image_viewer/image_loader.py`
  - 缓存记录 `(mtime_ns, 文件大小)`。
  - `cached_pixmap / cached_preview / request / prefetch` 读取时校验签名，变化则丢弃重载。
  - 新增 `invalidate_changed(paths)`。
  - 网络盘 `stat` 失败时保留旧缓存，避免瞬间闪空。
- `image_viewer/window.py`
  - `set_images`、`set_current_index` 时先校验签名。
  - 窗口重新激活时校验当前图片；变化则重新请求，不重置未变化的图片。
- `viewer/image_dock.py`
  - 悬浮窗缓存同样记录签名；加载新图集或窗口重新激活时丢弃已变化的缓存，并重新加载对应图片。

## 五、已知限制

1. 目前统一转换 RGB ICC；CMYK、16 位特殊格式转换失败时回退原值显示（不会崩溃）。
2. 独立查看器仍未自动应用 EXIF 方向（悬浮窗已修正）；这是显示旋转问题，与颜色无关。
3. 显示缓存版本升级后，首次打开图片会重新生成缓存，首屏可能比平时略慢。
4. 文件被外部更新后，需切换图片、重新打开查看器或让窗口重新获得焦点才会自动刷新；查看器保持焦点时不会主动轮询网络盘。

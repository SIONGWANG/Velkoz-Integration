# v1.24.3 报告：标签跨版本保留 + 移除失灵按钮

- 版本：1.24.3（基于 v1.24.2，分支 `1.24`）
- 日期：2026-11-24
- 范围：快捷标签 / 标签管理

---

## 一、问题现象

1. **「✅ 全选所有标签」「🗑️ 清空已选标签」点了没反应**，实际不起作用，用户也基本用不到。
2. **每次切换/解压新版本，标签库就没了**（只剩新版本自带的少量标签），
   之前积累的 15 个标签需要重新添加。

---

## 二、原因

### 失灵的批量按钮

快捷标签用 `st.pills` 渲染，每个标签行有自己的控件状态（widget state）。
两个按钮只改了 `st.session_state.selected_tags`，没有同步控件状态；
下一次重跑时，合并逻辑又以 pills 的旧选择为准，把 session 里的改动覆盖回去，
所以看起来“点了没用”。

### 标签丢失

标签库固定保存在**每个版本自己的** `config/tags.json`。
换一个版本文件夹 = 换了一份 `config`，自然读不到上一版本的标签；
新版本 zip 里带的是打包时的标签，所以表现为“标签没了”。

---

## 三、解决方案

### 1. 移除两个失效按钮

删除「📋 批量操作 → 全选所有标签 / 清空已选标签」整块（`zone_c.py`）。
已选标签仍可逐个点选/取消，单个记录需要清空时重新点一下已选标签即可。

### 2. 标签库存到跨版本共享位置（核心）

- 优先保存到本机数据盘：`D:\VelkozDATA\config\tags.json`；
  没有该目录时用 `%LOCALAPPDATA%\Velkoz\config\tags.json`；
  也可用环境变量 `VELKOZ_TAGS_FILE` 指定。
- 启动时**共享文件优先**；首次升级时若共享文件不存在，自动把当前
  `config\tags.json` 迁移过去，所以现有标签无需手工操作。
- 每次保存**双写**：共享文件 + 当前版本 `config/tags.json`（本地镜像，便于降级/备份）。
- 共享文件损坏时自动回退本地镜像，不会一启动就空白。
- 原子写入（临时文件 + `os.replace` + `fsync`），避免写一半损坏。

### 3. 标签库导出 / 合并导入

标签管理底部改为「📥 标签库备份 / 复用」：
- **⬇️ 导出当前标签库**：下载 `tags.json`，可用于备份或换电脑。
- **📥 合并导入到当前标签库**：选择旧版本 `config\tags.json`，
  去重合并标签与常用标签，并提示新增数量；不会覆盖/删除现有标签。

## 四、首次打开图片慢的优化（v1.24.3 同步修复）

### 原因

- 预加载函数把 `group['images']`（文件名）直接当完整路径用，漏了 `group['root']`，
  实际一直没预取成功，切换组时仍需现场读网络盘。
- 主页面首次打开图片走旧链路：`verify()` + 二次 `Image.open` + 全尺寸解码 + LANCZOS 缩放。
- 四宫格逐张串行读共享盘，5 张图就是 5 次等待。

### 优化

1. **修正预取路径**（root + 文件名），改为后台线程（2 并发）预取后面的组（最多 12 张）；
   切换上一组/下一组时直接命中磁盘缓存；换组会作废旧预取任务，避免抢带宽。
2. **四宫格并行预热**：首次渲染前把本组全部图片最多 4 并发读取/生成缓存，
   总等待从“逐张相加”变为“最慢一张”；单图模式下当前图先显示，同组其它图后台预热。
3. **显示专用快速解码**：JPEG 用 `draft()` 按 1/2、1/4、1/8 直接降采样解码，
   跳过 `verify()` 与二次打开；分辨率仍显示原图尺寸。
4. 磁盘缓存命中时完全不碰网络盘；回退缓存/占位图不再写入会话缓存，
   网络恢复后自动刷新为最新图。
5. 缓存写入加锁，后台多线程写入安全。

### 实测

- 合成 6000×4000 / 13MB JPEG：旧链路 0.461s → 新链路 0.165s（约 2.8 倍）。
- **局域网真实图片（4 张，共 20MB）**：顺序读取 0.97s → 并行预热 0.36s（约 2.7 倍）；
  缓存命中后 4 张共 0.037s。
- 4 张图并行预热 0.115s（本地小图），全部写入缓存。
- 预取调用 0.001s 返回（后台执行），5 个任务全部完成；新一代预取会作废旧任务。
- 3 次重试、旧缓存回退、无缓存占位图、降级期不预取均通过。

## 七、如何复用旧版本标签

**升级到 1.24.3 后（推荐，自动）**

- 直接把新版本解压到新文件夹运行即可；
- 第一次启动会把当前标签迁移到 `D:\VelkozDATA\config\tags.json`，
  以后所有版本共用，不再丢标签。

**手动合并（换电脑 / 旧版本已删除前）**

1. 打开「⚙️ 标签管理」；
2. 在「📥 标签库备份 / 复用」里点「从旧版本导入」，选择旧版本目录下的
   `config\tags.json`；
3. 点「📥 合并导入到当前标签库」，提示新增多少个即完成（重复标签自动去重）。

**备份习惯**

- 换版本/换电脑前，先点「⬇️ 导出当前标签库」，保存 `tags.json`。

## 八、已知限制

1. 标签共享只对 1.24.3 及以后版本生效；更早版本仍只读自己目录下的 `config/tags.json`。
2. 共享位置依赖 `D:\VelkozDATA`（或 `%LOCALAPPDATA%`）；若都不可写，会退回当前版本本地文件并记录日志。
3. 导入是“合并”，不会删除现有标签；需要删除请用标签库里的「标签 ✕」。
4. 常用标签最多显示在快捷区，数量过多时建议只保留 5 个左右。
5. 首次打开某张图且从未缓存时，仍必须真实读一次共享盘；并行预热只能减少“多张串行”的等待，
   无法消除单张图片本身的网络延迟。
6. 并行预热最多 4 并发；如果共享盘/服务器并发能力很弱，提升会打折，但不会比原来更慢。

## 九、回滚

1. 代码回滚：`git revert <本次提交>` 或切回 `v1.24.2`。
2. 标签数据不影响回滚：共享文件仍在 `D:\VelkozDATA\config\tags.json`；
   旧版本继续读自己目录的 `config/tags.json`（最后一次保存的镜像）。
3. 停用共享存储：删除/改名 `D:\VelkozDATA\config\tags.json`，
   并删除环境变量 `VELKOZ_TAGS_FILE`，即恢复为每版本独立存储。

## 1. 交付范围

### 1.1 管理中心新增“合格归档”

管理中心左侧导航新增：

```text
🗄️ 合格归档
```

页面按“选择批次与合格范围 → 输出目录与命名 → 预览 → 创建任务 → 开始复制 → 断点恢复/报告”的顺序组织，不改变正式质检三栏布局。

### 1.2 合格筛选

支持五种方式：

| 方式 | 说明 |
|---|---|
| 合格（默认） | 数据组状态为 `qualified/passed/completed/accepted/合格/修改后合格`，**或**导入记录结果为 `合格/修改后合格/pass/passed/qualified` |
| 按数据组状态 | 自定义逗号分隔状态值 |
| 按导入记录结果 | 读取 `imported_records.result`，用于其他验收员记录 |
| 手动选择 | 从批次数据组中逐条勾选 |
| 批次全部 | 明确归档整个批次 |

默认“合格”方式兼顾两种数据来源；若数据库尚未同步验收结果，页面提示可切换筛选方式。

### 1.3 输出起始层级

| 值 | 输出结构（`/` 表示目录） |
|---|---|
| `root` | 根目录名 / 大类目 / 小类目 / 团队 / 日期 / 模板 / 任务 |
| `category_l1` | 大类目 / 小类目 / 团队 / 日期 / 模板 / 任务 |
| `category_l2` | 小类目 / 团队 / 日期 / 模板 / 任务 |
| `team` | 团队 / 日期 / 模板 / 任务 |
| `date` | 日期 / 模板 / 任务 |
| `batch` | 模板 / 任务 |
| `custom` | 自定义前缀 / 模板 / 任务 |

批次层由命名模板替换；缺失层级跳过并记录说明。

### 1.4 命名模板

默认：

```text
{批次名}_{验收员}合格{合格数量}条
```

支持变量：`{批次名}`、`{验收员}`、`{合格数量}`、`{日期}`、`{大类目}`、`{小类目}`、`{团队}`、`{自定义}`。

- 未知变量直接报错；
- 缺失变量按回退规则处理并记录；
- Windows 非法字符统一清洗；
- 空名称回退为“未命名批次”。

### 1.5 复制前预览

预览只读源目录元信息，不创建输出目录：

- 输出根目录与渲染后的批次目录；
- 完整目录树（缩进文本）；
- 数据组数、文件数、占用空间；
- 目标已存在的数据组数；
- 每个数据组的源路径、目标路径、文件数、冲突与说明；
- 缺失变量回退说明；
- 路径安全错误（输出位于源目录内、自定义前缀含 `..` 等）。

### 1.6 只复制与冲突处理

- 源图片/TXT/CSV 始终以只读方式打开；不移动、不删除、不修改、不重命名。
- 目标文件使用独占创建（`O_CREAT | O_EXCL`），任何情况下不覆盖已有文件。
- 目标已存在且内容相同：跳过，保留原文件时间戳。
- 目标已存在且内容不同：标记 `conflict`，不覆盖，报告中列出路径。
- 目标目录存在额外文件：标记冲突，不删除额外文件。
- 两个数据组渲染到同一目标目录：预览标记重复，运行时拒绝第二个数据组复制。
- 不调用旧 `collect_reject_folders` / 归集删除逻辑。

### 1.7 复制校验

- 默认按“文件大小 + SHA-256”校验，可在界面关闭为仅大小校验。
- 每个数据组记录 `source_fingerprint` 与 `dest_fingerprint`。
- 校验不一致时删除本次刚创建的目标文件，并标记失败；不会删除源文件或用户已有目标文件。
- 校验结果写入 `archive_items`。

### 1.8 断点恢复

- 任务与每个数据组的完成状态持久化到 `archive_items`。
- 暂停/中断后再次运行：
  - `verified` 条目直接跳过，不重复复制；
  - `pending`、`failed`、`conflict` 条目重新尝试；
  - 已存在且相同的文件跳过，只补缺失文件；
  - 冲突解决后可直接继续同一任务。
- 服务层支持 `should_cancel` 回调；界面在任务中断后重新打开时，`running` 状态也提供“继续/重试未完成项”。

### 1.9 归档报告

每次运行结束（完成、失败、暂停）写两份报告到管理数据目录：

```text
D:\VelkozDATA\reports\archive\archive_<job_id>.md
D:\VelkozDATA\reports\archive\archive_<job_id>.json
```

报告包含：

- 任务、批次、源根目录、输出根目录、起始层级、模板、筛选、操作员；
- 数据组/已校验/跳过/冲突/失败/文件数/字节数汇总；
- 逐组状态、目标路径、冲突/失败说明；
- “源文件未被移动、删除或修改；目标已有文件未被覆盖”声明。

报告不写源目录。

## 2. 数据库

### 2.1 迁移 `0006_archive.sql`

新增：

- `archive_jobs`：任务、批次、源/输出根目录、起始层级、模板、筛选、状态、计数、字节数、哈希开关、报告路径、操作员、时间。
- `archive_items`：数据组、任务 ID、源/目标路径、状态、文件数、字节数、已复制字节、源/目标指纹、错误信息、时间。
- 索引：`batch_id`、`status`、`job_id`、`data_group_id`、`(job_id, status)`。

`archive_jobs.batch_id` 指向 `batches(id) ON DELETE SET NULL`；`archive_items.job_id` 指向 `archive_jobs(id) ON DELETE CASCADE`；`data_group_id` 指向 `data_groups(id) ON DELETE SET NULL`。

## 4. 只读与写边界

| 操作 | 源图片/TXT/CSV | 管理数据库 | 用户指定输出目录 |
|---|---|---|---|
| 批次/数据组选择 | 不访问 | 只读 | 不访问 |

| 归档报告 | 不访问 | 读任务/条目 | 不写 |

## 5. 已知限制与后续

1. 合格筛选依赖 `data_groups.status` 或 `imported_records.result`。如果当前验收结果只存在于旧 CSV、尚未导入/同步，请先使用“记录导入”，或选择“批次全部/手动选择”；本版本不直接解析旧 CSV 作为归档数据源。
2. 冲突处理为人工决策：不自动覆盖、不自动改名/换目录；解决目标差异后点击“继续/重试”即可。
3. 界面复制为同步执行，未提供运行中“取消”按钮；关闭/中断后可继续。服务层已支持 `should_cancel`，后续可接后台任务。
4. 哈希校验默认开启，大文件归档会多读一遍；可按需关闭为仅大小校验。
5. 目录树预览为文本缩进 + 明细表，未做图形化树控件。
6. 统计报表、批次/人员工作量汇总仍留给 v1.25.7。
7. 打包问题仍按用户要求暂缓。

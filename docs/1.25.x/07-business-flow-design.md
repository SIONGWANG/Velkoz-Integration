# 完整业务流程设计文档

> 目标：把“供应商提交 → 验收 → 归档 → 统计”串成可独立使用、可中断恢复、可追溯的流程
> 原则：每个环节可单独使用；失败不丢状态；原始数据只读；旧版兼容

---

## 1. 端到端流程

```text
供应商提交数据
  → 提交信息登记
  → 数据下载与入库
  → 格式检查
  → 数据扫描与识别
  → 人工确认批次
  → 翻译及语法检查
  → 验收任务管理
  → 正式图片质检
  → 验收记录汇总
  → 合格数据复制归档
  → 合格数量统计
  → 工作量统计
  → 最终报告
```

每个环节：

- 有明确输入/输出；
- 有独立状态；
- 可跳过；
- 失败可恢复；
- 有操作日志；
- 不修改源数据（除明确授权的质检保存）。

---

## 2. 角色与权限

默认单机单用户，但概念上区分：

| 角色 | 能力 |
|---|---|
| 管理员/本人 | 配置规则、管理数据库、执行归档、删除/修复授权 |
| 验收员 | 扫描、格式检查、翻译、正式质检、导出记录 |
| 其他验收员（旧版） | 继续用旧版；只通过导出 CSV/Excel 被本平台发现 |
| 供应商（外部） | 不接触本平台；只提供数据/网盘链接 |

平台默认不做账号体系；`operator` 来自设置/输入，用于记录归属。

## 3. 阶段设计

### 3.1 阶段 1：供应商提交登记

**输入**：供应商、团队、类目、提交日期、网盘链接、批次名、预计数量、下载路径、是否解压、备注。

**输出**：`supplier_submissions` 记录 + 可选批次草稿。

**规则**：

- 不要求飞书 API；
- 网盘链接只存文本；
- 不自动下载；
- 提交信息与批次可分离：先登记，后扫描确认。

**失败**：字段缺失 → 草稿；不阻塞后续。

---

### 3.2 阶段 2：数据下载与入库

**输入**：下载路径/解压后的目录。

**输出**：数据根目录 + 可选“待扫描”状态。

**规则**：

- 平台不负责下载/解压（本期）；
- 只记录路径、是否解压；
- 路径不存在 → 提示，不创建。

**失败**：路径不可读 → 记录，稍后重试。

---

### 3.3 阶段 3：格式检查（只读）

**输入**：批次目录/根目录 + 模板。

**输出**：检查 run + 任务结果 + 异常明细 + 报告。

**规则**：

- 默认只读；
- 不自动修复；
- 可重跑、仅查异常；
- 报告可打开任务目录；
- 异常清单可带到正式质检人工判断。

**失败**：

- 单任务异常不终止全量；
- 报告失败不影响检查记录；
- 中断保留已完成结果。

---

### 3.4 阶段 4：数据扫描与识别（只读）

**输入**：一个或多个根目录 + 规则方案。

**输出**：候选批次 + 数据组 + 诊断原因。

**规则**：

- 扫描器只发现，不确认、不改数据；
- 候选必须人工确认才入库；
- 识别结果可解释；
- 支持多根目录、多规则、多层级。

**失败**：

- 0 候选必须给原因；
- 权限/断线 → 部分结果 + 错误；
- 可取消/重扫。

---

### 3.5 阶段 5：候选批次人工确认

**状态**：

```text
pending（待确认）
confirmed（已确认）
ignored（已忽略）
abnormal（结构异常）
partial（部分识别）
duplicate（重复批次）
rescan（待重新扫描）
```

**操作**：

- 确认；
- 修改身份字段；
- 合并批次；
- 拆分批次；
- 忽略；
- 重新扫描；
- 查看原因。

**规则**：

- 确认后生成 `batch`/`data_groups`；
- 修改规则不自动改已确认批次；
- 所有操作写日志。

---

### 3.6 阶段 6：翻译与预审（原生）

**输入**：批次 + 中文/英文 TXT 配对 + 模型配置。

**输出**：英文 TXT（原生生成，确认后写入）+ 翻译记录 + 费用记录 + 翻译报告。

**规则**：

- 原生实现：读取中文 TXT → 调用 Ark / 百炼千问 / OpenAI 兼容接口 → 预览 → 确认后写英文 TXT；
- 写前备份、原子写入；失败不覆盖已有有效英文；
- 重新翻译需确认覆盖；保留历史版本/备份；
- 英文语法检查、中英文一致性检查只出建议，不自动改；
- API Key 使用 Windows DPAPI 加密保存，界面掩码，不进日志/报告；
- Token/费用按单价配置记账，可导出报告；
- 失败可重试、可跳过已翻译、可指定重新翻译；
- 兼容入口：只读导入原工具 `translation_report_*.csv` / `cost_report.csv`，用于历史费用/记录迁移；
- 不读取/复制原工具 API Key，不调用其未公开内部接口。

**明确限制**：

- 没有原工具源码/Prompt，**不能保证翻译质量与原工具完全一致**；
- 默认 Prompt 由本项目提供，允许用户编辑与恢复默认。

**失败**：

- 单条失败不终止全量；失败项保留原英文 TXT 不变；
- 报告失败不影响翻译记录；
- 任务可取消，已完成项不回滚。

---

### 3.7 阶段 7：验收任务管理

**输入**：已确认批次/子批次。

**输出**：验收任务（谁、何时、哪个批次、多少条）。

**规则**：

- 一个大批次可拆多个子批次；
- 多个团队可处理不同批次；
- 批次可暂停/重开/归档；
- 任务与操作员关联；
- 状态变化留日志。

---

### 3.8 阶段 8：正式图片质检（现有核心）

**输入**：数据根目录 + 操作员 + CSV 选择。

**输出**：CSV 记录 + 截图 + Excel。

**规则**：

- 保持现有三栏/快捷键/查看器/查询/导出；
- CSV 仍是权威；
- 数据库只做事件索引；
- 不改变图片/TXT 命名；
- 不限制图片数量；
- 主界面不被新模块挤压。

**风险点（已确认保持现状）**：

- 跨天 CSV 写入旧文件（保持现状）；
- TXT 写回源目录（保持现状）；
- 证据截图路径解析（兼容保留）。

> 以上三项为 `00-decisions.md` D-002 确认的行为基线，本版本不改默认行为，只写操作日志。

---

### 3.9 阶段 9：验收记录汇总

**输入**：本机 CSV + 其他验收员导出表。

**输出**：统一验收事件索引 + 批次统计。

**规则**：

- 本机 CSV 直接索引；
- 他人 CSV 只读导入；
- 保留原始标签/备注；
- 同一 CSV 增量导入；
- 不要求本机有同名标签定义；
- 不修改原文件。

**状态诚实**：

- 已发现验收表；
- 已导入；
- 尚未发现可导入表；
- 文件存在但结构无法识别；
- 导入失败。
- **不虚构实时进度。**

---

### 3.10 阶段 10：合格数据归档

**输入**：批次 + 合格筛选 + 输出起始层 + 命名模板。

**输出**：复制后的目录树 + 归档报告。

**规则**：

- 只复制，不移动；
- 不删源、不覆盖源、不改 TXT/CSV/图片；
- 复制前预览目录树/文件数/空间/冲突；
- 复制后校验大小（必要时哈希）；
- 支持断点恢复；
- 目标已存在不直接覆盖。

---

### 3.11 阶段 11–13：统计与报告

**输入**：验收事件、格式检查、翻译、归档记录。

**输出**：

- 批次统计；
- 验收人员统计；
- 错误类型统计；
- 工作量；
- 日报；
- Excel。

**规则**：

- 可追溯到具体批次/原始记录；
- 标签兼容历史；
- 统计不修改原始数据；
- 缓存可重建。

## 4. 状态机

### 4.1 批次状态

```text
registered
  → downloaded
  → scan_pending
  → confirmed
  → format_checked
  → translating
  → accepting
  → accepted
  → archived

任意状态 → paused
paused → 原状态（reopen）
任意状态 → blocked（结构/权限/数据异常）
```

### 4.2 候选批次

```text
pending → confirmed
pending → ignored
pending → abnormal → rescan → pending
pending → partial → confirmed（人工补全）
pending → duplicate → merged/ignored
```

### 4.3 格式检查

```text
running → completed
running → cancelled
running → failed
completed → recheck（新 run）
```

### 4.4 翻译

```text
not_started → pending → running → done
                         ├→ partial → retry
                         └→ failed → retry/skip
```

### 4.5 验收

```text
not_started → in_progress → done
                    ↑         │
                    └ reopened┘
```

### 4.6 导入

```text
discovered → classified → previewed → importing → completed
                                             ├→ partial
                                             └→ failed → retry
```

### 4.7 归档

```text
preview → running → completed
             ├→ paused → running（断点）
             └→ failed → retry
```

## 5. 每个阶段的失败与恢复

| 阶段 | 失败 | 恢复 |
|---|---|---|
| 提交登记 | 字段缺失 | 草稿，稍后补 |
| 下载/解压 | 路径不存在 | 记录，重试 |
| 格式检查 | 单任务异常/报告失败/中断 | 保留已完成；重跑异常；重建报告 |
| 扫描 | 权限/断线/0 候选 | 部分结果 + 原因；重扫 |
| 确认 | 规则冲突/重复 | 人工修改/合并/忽略 |
| 翻译 | API 超时/失败 | 重试；不覆盖有效英文 |
| 质检保存 | CSV 占用 | 现有重试 + 提示关闭 |
| 记录导入 | CSV 结构未知 | 标记 unclassified；不导入 |
| 归档 | 冲突/中断/磁盘满 | 跳过/重命名/断点恢复 |
| 统计 | 数据缺失 | 显示“未知”，不臆造 |

## 7. 日常使用示例

### 7.1 新批次到达

```text
1. 工作台看到“待处理提交”。
2. 登记供应商/团队/日期/网盘链接/路径。
3. 格式检查：选批次目录 + 模板 → 预览 → 开始。
4. 查看异常：缺图/缺 TXT/编号不连续 → 与供应商沟通。
5. 扫描：选根目录 + 规则方案 → 查看候选 + 原因。
6. 确认批次 → 生成数据组。
7. 翻译：生成待翻译清单 → 原生批量翻译 → 预览 → 确认写入 → 语法/一致性检查。
8. 正式质检：加载文件夹 → 按原有流程验收。
9. 其他验收员导出 CSV → 平台只读导入。
10. 合格归档：预览 → 复制 → 校验。
11. 统计/日报：导出 Excel。
```

### 7.2 只需要格式检查

```text
选择目录 → 选模板 → 开始 → 导出报告
（不建批次、不扫描、不质检）
```

### 7.3 只需要正式质检

```text
直接“加载文件夹” → 原有流程
（不要求先格式检查/翻译/建批次）
```

### 7.4 返修批次

```text
重新扫描 → 差异对比 → 只检查异常 → 重新质检 → 重新归档
```

## 8. 与其他验收员的协作边界

需求明确：

- 所有验收员访问同一局域网共享目录；
- 其他人可能用旧版；
- 他们自己选批次、完成验收、导出记录；
- 本平台只能在导出后发现。

因此：

1. **不要求他们升级**；
2. **不要求他们改导出方式**；
3. **不要求他们建新目录**；
4. 平台只读发现导出表；
5. 状态只描述“发现/导入/无法识别”，不描述实时进度；
6. 保留原始标签/备注，即使本机没有定义；
7. 不修改他人原始表。

## 9. 统计口径

### 9.1 批次统计

- 总数据量 = `data_groups` 数；
- 已格式检查 = 最近一次 run 覆盖的任务数；
- 格式异常 = `fail` 数；
- 已翻译 = `translation_items.status=translated`；
- 翻译失败 = `failed`；
- 已验收 = 有 `acceptance_events` 的组数；
- 合格/不合格 = 最新事件结果；
- 未验收 = 总数 - 已验收。

> v1.25.7 实现说明：当前管理数据库没有独立的 `acceptance_events` 表，验收事件以 `imported_records.result` 为准（导入记录即可追溯的验收事件）；批次级数字仍读取 `batches.qualified_count/rejected_count/remaining_count` 快照。

### 9.2 人员统计

- 按 `operator` + 日期 + 批次；
- 验收数量、合格、不合格、合格率、工作量；
- 工作量可配置权重（按条数/按图片数/按耗时）。

### 9.3 错误类型

- 复用现有标签；
- 按标签/批次/团队/日期；
- 兼容历史标签（原文保留）；
- 未定义标签也统计。

### 9.4 日报

- 当日新增；
- 当日格式检查；
- 当日翻译；
- 当日验收/合格/不合格；
- 当日剩余；
- 可导出 Excel。

## 11. 关键业务规则

1. **格式检查默认只读**；修复另立、需确认。
2. **扫描只发现，不修改**；候选必须人工确认。
3. **归档只复制，不移动**；不删源。
4. **导入只读**；不改他人 CSV。
5. **CSV 仍是验收权威**；数据库是索引。
6. **同一图片 ID 可在不同批次重复**；身份必须含批次。
7. **同一条数据可多次验收**；历史不覆盖。
8. **标签原文保留**；不要求本机定义。
9. **没有验收表 ≠ 没工作**；状态要诚实。
10. **任何覆盖/删除都需显式确认**。
11. **长任务不阻塞 UI**；可取消/恢复。
12. **每步有日志**；可追溯。

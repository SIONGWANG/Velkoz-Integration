## 1. 交付范围

### 1.1 业务目录配置

管理设置新增“业务数据目录（待验 / 申请终验）”：

- 共同项目根目录：自动识别 `02-待验数据`、`03-申请终验`；
- 也可分别填写两个独立网络路径；
- 支持多个项目配置，单独启用/停用/修改/删除/刷新；
- 配置写入管理数据库 `project_roots`，重启后仍有效；
- 目录不存在、网络不可访问、无权限时显示具体错误，不自动创建目录；
- 明确拒绝 `00-试做情况`、`01-素材仓库` 或项目父目录作为扫描根。

首次打开工作台且未配置目录时显示配置引导；配置后默认进入数据验收工作台。

### 1.2 双来源目录发现

新增 `modules/workspace/discovery.py`：

- `pending_acceptance`：只扫描配置的待验目录；
- `final_acceptance`：只扫描配置的申请终验目录；
- 复用扫描规则的任务层、文件槽位和忽略规则；
- 支持不同层级、可选中间层、类目缺失、`1107` 这类四位日期、不同团队/批次命名、多级数据目录和超过 7 层的深度；
- 跳过 `Thumbs.db`、`.DS_Store`、`._*`、`__MACOSX`、`_00_Evidence_*`、`_质检记录`、程序临时目录；
- 不按“返修/合格数据”等业务词盲目排除；
- 同一路径的批次不会因重复刷新重复创建；
- 网络断开或目录不可读时只记录访问失败，不删除历史批次。

### 1.3 数据验收工作台

- 管理中心默认入口改为 `🏠 数据验收工作台`；
- 顶部真实统计：待验批次、申请终验批次、待格式检查、待翻译、待正式验收、存在异常；
- 四个区域：待验数据、申请终验、全部批次、待确认；
- 批次列表包含名称、大类目、小类目、团队、日期、数据量、图片数、格式状态、格式异常、翻译状态、验收状态、最近活动；
- 支持搜索、团队、类别、日期、格式/翻译/验收状态筛选和排序；
- 批次操作全部以当前 `batch_id` 为上下文：
  - 查看详情；
  - 格式检查（自动带入批次路径和 `batch_id`）；
  - 翻译（自动带入批次路径和 `batch_id`，自动扫描 TXT）；
  - 进入正式质检（把批次路径传给现有质检入口）；
  - 查看验收记录（预选当前批次）；
  - 合格归档（预选当前批次）。
- 完整路径只放在批次详情折叠区，主列表优先展示业务信息。

### 1.4 批次详情

新增/整合以下区域：

- 顶部：批次名称、来源类型、项目、类别、团队、日期、数据量、图片数；
- 处理进度：批次发现 → 格式检查 → 翻译预审 → 正式验收 → 验收记录汇总 → 合格归档；
- 格式检查：次数、最近检查、模板、通过/失败/警告、错误明细，支持重新检查和仅检查上次异常；
- 翻译预审：中/英 TXT 数、已完成/待翻译/失败、模型、Token、费用、最近时间，支持翻译缺失项和失败重试；
- 验收记录：验收员、记录数、合格/不合格、其他、备注、标签、来源 CSV、导入时间；
- 合格归档：已校验/跳过、冲突、失败、归档条目；
- 来源关联：申请终验批次可按共同任务 ID 人工关联原始待验批次，不按名称相似自动合并。

### 1.5 批次关联修复

- `ui/pages/format_check.py` 创建 `FormatCheckRequest` 时传入 `batch_id`；
- `ui/pages/precheck.py` 创建 `TranslationRequest` 时传入 `batch_id`；
- 从批次详情启动时不再要求手工填写路径；
- 格式检查完成后更新 `batches.format_status`；
- 翻译完成后更新 `batches.translation_status`；
- 导入验收记录后按 `imported_records.result` 刷新合格/不合格/剩余与验收状态；
- 工作台和批次详情优先按真实运行记录计算状态，未检查显示“未检查”，无验收导出表显示“暂无已导入验收记录”。

## 5. 工作台使用说明

1. 打开管理中心，默认进入“数据验收工作台”；
2. 首次使用填写项目根目录，点击“检测待验 / 申请终验目录”，确认后保存；
3. 点击“刷新待验目录”“刷新申请终验”或“全部刷新”；
4. 刷新完成后在“待确认”确认新批次；已确认批次不会再次要求确认；
5. 在待验/申请终验/全部批次中搜索、筛选、排序；
6. 选择批次后直接点击格式检查、翻译、正式质检、验收记录或合格归档；
7. 批次详情中查看处理进度、检查明细、翻译明细、验收记录、归档和来源关联；
8. 路径只出现在批次详情“来源目录与路径”折叠区和管理设置中。

## 6. 已知限制

1. 首次发现的新批次仍需要人工确认；本版本不自动合并同名或相似批次。
2. 目录身份使用路径规则 + 启发式（团队“提交”、日期、类目）推导；极不规则目录可能需要人工确认或在候选说明中查看原因。
3. 刷新为后台线程内的同步扫描，未做成可跨进程恢复的持久任务；关闭应用会中断当前刷新。
4. 发现阶段只读取目录名、文件名、大小和修改时间，不计算文件内容哈希，以避免局域网大目录负担。
5. “进入正式质检”只把批次路径传给现有质检入口，仍需在正式质检界面执行原有扫描/加载流程，未改变质检核心。
6. 申请终验来源关联要求至少一个共同任务 ID；没有共同任务时不允许关联。
7. 打包问题仍按用户要求暂缓。

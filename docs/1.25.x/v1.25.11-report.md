## 1. 本次目标

1. 把管理中心重做为“以批次为核心”的卡片层级：大类 → 小类 → 三级类 → 批次，缺层自动跳过。
2. 扫描队列跨页面、跨目录保留，只有手动移除才消失；点“开始扫描”才真正扫描。
3. 验收记录按 `_质检记录/验收员` 绑定；多验收员弹窗选择全部绑定 / 只绑一个 / 都不绑定。
4. 批次主状态只保留“新提交 / 已完成”，检查、翻译为独立子状态；状态可手动修改并写日志。
5. 格式检查按大类/小类/三级类绑定图片数量规则，支持批量勾选；页面只显示总数/成功/失败，明细导出 Excel；与库中合格编号查重。
6. 翻译只处理 `03-申请终验`，按卡片勾选批次，调用本机 `http://localhost:8765` HTTP API；预览只读，确认后备份英文 TXT 再写入。
7. 统计按大类、小类、团队、合格情况汇总，全部来自管理数据库。
8. 编号查询输入编号查位置，可进入所在批次；历史只查数据库，不遍历文件夹，不影响当前验收。
9. 管理中心仍留在审视之眼同一个 Streamlit 程序内，不新增第二个服务或独立前端。

## 2. 功能实现

### 2.1 卡片工作台与扫描队列

- 新工作台：`ui/pages/catalog_workbench.py`。
- 层级卡片逐层展示；上级卡片同时显示“批次口径”和“数据量口径”的已完成/未完成。
- 缺失小类、三级类时直接跳过，不判错。
- 卡片勾选后进入扫描队列；队列写入 `catalog_queue`，切换页面、切目录后仍保留，只有手动移除才消失。
- “开始扫描队列”只处理队列中未完成的项；已 `done` 的批次跳过，并提示到批次详情使用“重新扫描验收记录”。
- 批次详情：`ui/pages/catalog_batch.py`，显示编号、验收记录、验收员文件夹、状态日志、路径、手动改状态、格式重检、最近翻译。

### 2.2 验收记录扫描与状态

- 核心：`modules/workspace/catalog_scan.py`。
- 只读 `_质检记录` 下的 CSV/XLSX；优先 CSV，忽略 `.bak`，仅在没有 CSV 时使用 XLSX。
- 用设置中的验收员标签匹配文件夹名；团队层的 `_质检记录` 直接忽略。
- 多验收员时弹窗三选一；都不绑定、空验收员文件夹都保持 `新提交`。
- 扫描成功并绑定验收员后主状态变 `已完成`；记录写入 `catalog_records`，截图按批次目录解析为绝对路径。
- 状态变更写入 `catalog_status_log`；批次详情可手动修改主状态。

### 2.3 格式检查

- 核心：`modules/workspace/catalog_format.py`；页面：`ui/pages/catalog_format.py`。
- 不改现有规则引擎；按类目绑定图片数量，三级类优先、其次小类、最后大类。
- 未配置规则的批次只记录图片数量，检查状态保持 `未检查`，不判失败。
- 支持多批次批量勾选、筛选、全选当前筛选。
- 页面只显示批次总数、通过、失败、未配置、编号总数、通过/失败编号、重复编号；逐编号明细导出 Excel。
- 全对 → `已检查`；有错 → `检查失败`；批次详情与格式页均可重新检查。
- 与库中合格编号查重，命中给出警告并写入 Excel“重复编号”工作表。
- Excel 含 4 个工作表：总览、批次汇总、检查明细、重复编号。

### 2.4 翻译对接 8765

- 核心：`modules/workspace/catalog_translation.py`；页面：`ui/pages/catalog_translation.py`。
- 只列 `03-申请终验` 批次，卡片勾选；先“预览所选”（只调用 `/api/scan`），再勾选确认后“开始翻译所选”。
- 调用公开接口：
  - `GET /health` 测试连接；
  - `POST /api/scan` 读取编号、`_CH.txt` / `_EN.txt` 状态；
  - `POST /api/translate` 提交批次、编号列表、模型与提示词。
- 调用前把将受影响的英文 TXT 复制到
  `D:\VelkozDATA\backups\translation\<batch_id>\<timestamp>\`；
  备份失败则不调用翻译接口。
- 英文 TXT 的实际写入由 8765 工具完成；平台只做备份、调用、状态与审计。
- 翻译成功写 `translated`，有失败写 `translation_failed`，并写入 `catalog_status_log`。
- API Key 使用 Windows DPAPI 加密保存在本机，界面只显示掩码，不写入日志/报告。

### 2.5 统计

- 核心：`modules/workspace/catalog_stats.py`；入口：`ui/pages/stats.py` 的第一个标签“批次统计”。
- 统计口径全部来自 `catalog_*` 表：
  - 批次数、数据量、已完成批次；
  - 合格、不合格、未覆盖、合格率；
  - 按大类、小类、三级类、团队汇总；
  - 格式检查、翻译状态分布。
- 原有统计页、Excel 导出保留。

### 2.6 编号查询

- 页面：`ui/pages/catalog_query.py`；入口放在主侧栏“🔎 编号查询”。
- 支持一次查询多个编号（逗号/空格/换行，最多 50 个）。
- 查位置：大类、小类、三级类、团队、日期、批次、编号文件夹路径；可直接“进入批次”。
- 历史：验收判定、原因、标签、截图、验收员、质检时间；格式检查历史；翻译历史。
- 全部只查数据库，不遍历源目录，不修改文件。

### 2.7 导航与界面

- 主入口：验收工作台、编号查询、记录导入、数据统计、设置。
- 高级工具：目录索引、批次格式检查、批次翻译、合格归档。
- 旧页面（批次总览、团队与类别、数据扫描、候选确认、格式检查、翻译预审）先从导航隐藏，代码保留，深链接仍可用。
- 工作台工具栏新增“格式检查”“批次翻译”。
- 统一卡片、指标、主按钮、标签页样式；不引入新的前端框架。

## 6. 已知限制

1. **真实模型翻译未在本机验证**：本机只确认 8765 健康检查与扫描接口；没有模型 API Key，因此用本地 mock 验证 `/api/translate` 的请求结构、备份、状态与结果处理。接入真实 Key 后需再跑一次小批次。
2. **8765 的翻译接口没有公开文档**：请求字段通过其内置页面的公开前端代码核对（`api_key`、`model`、`provider`、`base_url`、`root_dir`、`folders`、`suffix`、`concurrency`、`prompt`、`options.mode`）。若 8765 升级改字段，需要同步调整。
3. **格式图片数取“编号文件夹直接文件”**：当前 Testdata 的图片在子目录，直接图片数为 0；测试时规则临时设为 1，测试后已恢复为 0（未配置），避免误判。
4. **翻译预览不调用模型**：预览只显示“待翻译/跳过/缺中文”，不展示译文；需要预览译文时必须真正调用模型。
5. **旧页面仅隐藏**：深链接仍可访问；尚未物理删除，待用户确认砍留清单。
6. **扫描/格式/翻译都不修改图片/TXT/CSV**；翻译的英文写入由 8765 工具执行，平台已做写入前备份。

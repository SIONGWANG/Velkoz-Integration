### 2.2 批次管理服务

```text
modules/batch_management/
├── __init__.py
└── service.py
```

能力：

| 方法 | 说明 |
|---|---|
| `list_runs` | 扫描记录列表 |
| `list_candidates` | 按扫描记录/状态查询候选 |
| `candidate_groups` | 候选包含的数据组 |
| `confirm_candidate` | 确认候选生成批次，可只确认部分数据组 |
| `update_candidate` | 修改批次名、身份字段、备注和候选状态（待确认/异常/待重扫/部分/重复） |
| `ignore_candidate` | 忽略候选并记录原因 |
| `merge_candidates` | 合并多个未确认候选，自动去重数据组 |
| `split_candidate` | 拆出部分数据组生成批次，剩余自动生成待确认候选 |
| `diff_runs` | 对比两条扫描记录的数据组与候选变化 |
| `list_batches` / `batch_groups` | 查看已确认批次和数据组 |

约束：

- 已确认候选不能再次确认生成新批次（幂等返回原批次）；
- 已忽略候选不能直接确认；
- 已确认/已忽略候选不能修改、合并或拆分；
- 合并和拆分都会保留候选来源信息（`source` 为 `scan` / `merge` / `split`）；
- 保存扫描记录时把候选包含的数据组路径写入 `group_paths_json`，避免嵌套批次按路径前缀串组；
- 确认批次保存规则方案 ID、规则版本 ID 和扫描时的规则快照，规则修改不回写已确认批次；
- 所有确认、忽略、修改、合并、拆分均写入 `operation_logs`。

### 2.3 页面

```text
ui/pages/batches.py
```

五个标签页：

1. **候选确认**：候选表格、批次名、数据组多选、身份 JSON、确认/忽略；

5. **已确认批次**：批次列表、数据组、状态日志。

入口：

- 正式质检页 → “更多设置” → “1.25 管理平台（预览）” → “🧩 候选确认”；

## 5. 只读与数据保护

本版本承诺：

1. 确认/合并/拆分只写管理数据库；
2. 不移动、复制、删除、重命名或修改源图片/TXT/CSV；
3. 数据组文件索引只读取文件名、大小和修改时间；
4. 不跟随符号链接/junction；
5. 旧质检保存仍写回源 TXT（保持现状）；
6. 旧“不合格归集”仍复制后删除源目录（保持现状）；
7. 跨天记录仍按原逻辑写入旧 CSV（保持现状）。

---

## 6. 已知限制

1. 批次确认后暂不支持反向“撤销确认”或删除批次；后续版本补充状态流转。
2. 合并/拆分使用候选现有数据组路径，不重新扫描源目录。
3. 差异对比基于扫描记录快照；若两次扫描规则不同，候选变化可能包含规则差异。
4. `sub_batches` 表已创建但本版本未使用，留给后续子批次/分包。
5. 批次状态目前只有 `confirmed`，验收/翻译/格式状态字段已预留但未流转。
6. 大量候选时页面一次性加载；后续可加分页/筛选。
7. 打包脚本未修改（按用户决定暂缓）。

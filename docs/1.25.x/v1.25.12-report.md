# v1.25.12 修复报告：待验数据忽略已导出的“合格数据”目录

> 版本：`1.25.12`（基于 `v1.25.11`，commit `d8cb804`）
> 日期：2026-11-14
> 类型：目录索引口径修复，无数据库结构变更

## 1. 问题背景

`02-待验数据` 下会回流已经导出过的合格批次，目录名通常含“合格数据”，例如：

- `新标_刘斯畅_20261112_合格数据_44组`
- `1028-人物景-50组_合格数据_7组`

这些目录是“已经合格并导出”的结果，不是还需要验收的批次。旧逻辑会把它们当成本地待验批次索引，导致：

- 工作台批次数、编号数偏大；
- 同一批数据在待验与终验两侧重复出现；
- 统计、编号查询与扫描队列出现误导性条目。

`03-申请终验` 本身就是合格数据批次，批次名普遍带 `_合格数据_N组`，必须保留，不能被同一条规则误伤。

## 2. 变更内容

### 2.1 目录索引

- `modules/workspace/catalog_service.py`
  - 新增常量 `PENDING_IGNORE_KEYWORDS = ("合格数据",)`。
  - 新增 `default_ignore_patterns(source_type)`：仅当 `source_type == "pending_acceptance"` 返回内置关键词，终验返回空。
  - `sync_root()` 将用户忽略规则与内置规则合并去重后传给 `detect_batches()`。
  - 匹配口径沿用 `detect_batches` 的“相对路径任意一段包含关键词即跳过”，因此批次名或上层目录带“合格数据”都会被忽略。

### 2.2 统计与查询

- `modules/workspace/catalog_stats.py`：`_where()` 固定追加 `b.is_active = 1`。
- `ui/pages/catalog_query.py`：位置查询、验收历史、格式历史、翻译历史统一加 `(b.id IS NULL OR b.is_active = 1)`。

### 2.3 界面说明

- `ui/pages/catalog_settings.py`、`ui/pages/catalog_sync.py`：增加“内置规则（不可删除）”说明，明确只对 `02-待验数据` 生效。

### 2.4 测试

- `tests/test_v12511.py`：新增 `test_pending_ignores_qualified_exports_but_final_keeps`。
  - 同名目录放在待验：被跳过；
  - 同名目录放在终验：正常保留。

## 3. 数据兼容与迁移

- 无表结构变更，schema 仍为 14。
- 已存在的“合格数据”待验批次不物理删除，只置 `catalog_batches.is_active = 0`，保留行、状态与日志，便于追溯。
- `catalog_queue` 中指向已忽略批次的排队项一并删除。
- 源目录、图片、TXT、CSV 一律只读，不重命名、不移动、不删除。

清理脚本要点：

```sql
UPDATE catalog_batches
   SET is_active = 0, updated_at = :now
 WHERE source_type = 'pending_acceptance'
   AND is_active = 1
   AND (name LIKE '%合格数据%' OR batch_path LIKE '%合格数据%');

DELETE FROM catalog_queue
 WHERE batch_id IN (SELECT id FROM catalog_batches WHERE is_active = 0);
```

随后对两个真实项目分别重新执行 `sync_root` 刷新索引。

## 6. 已知限制

1. 内置关键词是精确中文匹配“合格数据”，若以后导出目录改用其他命名（如“已合格”“pass”），需要补充关键词或改用团队自定义规则。
2. 已完成的历史批次被置为 `is_active = 0` 后，工作台与统计默认不再显示；需要追溯时可按 `is_active = 0` 查询数据库。
3. 项目列表中仍可能存在同名项目（同一共享盘路径添加了两次），界面显示相同，需用户自行删除重复项。
4. 本机数据库重置后，项目配置、忽略规则、标签与历史索引需要重新建立；`D:\VelkozDATA\backups` 中保留重置前备份。

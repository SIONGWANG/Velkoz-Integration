# v1.24.4 报告：缓存按批次自动清理 + 合格率口径修正

- 基于版本：v1.24.3（提交 `3e20427`，标签 `v1.24.3`）
- 版本号：`1.24.4`
- 日期：2026-11-25

---

## 一、问题

### 1. 图片缓存需要人手动清理
v1.24.2/1.24.3 的显示缓存虽然有 2GB / 60 天的自动上限，但：

- 上限偏大，普通办公电脑仍可能被占掉几个 GB；
- 只在写入累计 200 次时触发清理，开机不检查；
- 清理策略是“按时间保留”，和实际“一个批次几个小时到几天就做完”的用法不匹配；
- 用户不知道缓存存在，也不会主动去设置页清理。

### 2. 合格率算错
A 区显示：

```
合格率 = (合格 + 修改后合格) / 总数
```

未检、待定也被算进分母，导致合格率长期偏低。例如 3 合格、2 修改后合格、4 不合格、1 待定、5 未检：

- 旧算法：`(3 + 2) / 15 = 33.3%`
- 正确算法：`(3 + 2) / 9 = 55.6%`

「全部验收完成」面板同样使用了错误分母。

### 3. 状态面板占屏幕
6 个 `st.metric` 排成 3 行，加上 3×2 筛选按钮，左侧栏被占掉大量高度。

---

## 二、修改方案

### 1. 缓存只服务当前批次（自动清理，无需手动操作）

采用“换批次才清”的策略（按用户确认）：

- **打开/加载新批次**：后台删除不属于当前批次目录的缓存，当前批次保留（同一批次重新扫描不会清）。
- **不因单个批次做完而清空**：方便完成后回看、返修。
- **启动兜底**：后台清理临时文件、孤儿条目，并按上限收紧一次。
- **硬上限 500MB**：只有单个批次特别大时才触发，超限一次清到 80%，避免频繁抖动。
- **磁盘空间保护**：
  - 剩余 <2GB：预算收紧到 100MB；
  - 剩余 <500MB：暂停写入新缓存，仍可读旧缓存；
- **设置页**：显示当前缓存大小/张数，说明“换批次自动清理”，保留「🧹 清空图片缓存」。

效果：正常情况下磁盘里只有正在做的这一个批次，通常几十 MB，用户完全不用管。

### 2. 合格率改为“只算已判定”

统一抽到 `utils.summarize_review_statuses()`：

```
已判定 = 合格 + 修改后合格 + 不合格
合格率 = (合格 + 修改后合格) / 已判定
进度   = (已判定 + 待定) / 总数
```

- 未检、待定不进合格率分母；
- A 区与完成面板共用同一个函数，避免两处口径不一致；
- 卡片下方直接注明口径。

### 3. A 区面板紧凑化

- 6 个 `st.metric` → 一张横向卡片：合格率、渐变色进度条、5 个状态数量；
- 6 个筛选按钮 → 单行 `st.pills`，标签带数量（如「未检·14」）；
- 整体高度约减少一半，筛选仍然是一次点击；
- 筛选变化会触发整页刷新，B/C 区同步更新。

## 五、升级与迁移

- 直接覆盖安装即可，**不需要手动处理缓存**；
- 第一次启动时会在后台清理临时文件、孤儿条目，并按 500MB 收紧；
- 缓存目录仍是 `D:\VelkozDATA\cache\display`（或 `%LOCALAPPDATA%\Velkoz\display_cache`）；
- v1.24.4 起不再使用“60 天保留”策略；旧缓存会在启动/换批次时被回收。

---

## 六、已知限制

1. 缓存只按“批次根目录”区分；如果两个批次共用同一个根目录，会视为同一批次。
2. 打开新批次后，旧批次缓存被删除；回到旧批次会重新读一次共享盘（这是按“只保留当前批次”的选择）。
3. 首次查看某张从未缓存的图片，仍需要真实读一次共享盘；缓存只能减少重复读取。
4. 合格率不含未检、待定；如果希望把待定算入分母，可后续加开关，但当前按用户确认的口径执行。
5. 显示缓存的硬上限是 500MB，环境变量 `VELKOZ_DISPLAY_CACHE_MAX_MB` 可临时覆盖（测试/特殊部署）。

---

## 七、回滚

1. 代码回滚：`git revert <本次提交>` 或切回 `v1.24.3`。
2. 缓存数据：回滚后旧版本仍按 2GB / 60 天策略工作，不需要迁移。
3. 合格率：回滚后恢复旧口径（含未检/待定），仅显示变化，不影响已保存的质检记录。

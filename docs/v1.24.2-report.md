# v1.24.2 报告：局域网图片加载容错 + 查看器左右缩放同步

- 版本：1.24.2（基于 v1.24.1，分支 `1.24`）
- 日期：2026-11-24
- 范围：主界面图片显示链路、内置图片查看器双图缩放行为

---

## 一、问题现象

### Bug 1：百度网盘下载时主页面图片加载不出来

- 软件自身几乎不占外网带宽，图片来自局域网共享盘（SMB，`\\10.10.111.227\...`）。
- 一旦用百度网盘下载大文件，主页面图片经常只剩占位/空白，提示「加载失败」。
- 查看器、预加载、主界面共用同一份 SMB 读取链路，网络被占满时读取会长时间阻塞或超时。

### Bug 2：双图查看器锁定后，点另一侧会跳动

- 开启「锁定视图」后，在一张图上放大，再点另一张图，另一张图的缩放会跟着变，看起来“跳一下”。
- 用户期望：**默认左右各自独立**，点哪张只缩放哪张，另一张大小不变；
  需要时再手动打开「左右缩放同步」，让两侧一起放大/缩小/平移。

---

## 二、原因分析

### Bug 1

1. 主界面显示图 (`get_display_image_bytes`) 原先只依赖 `st.session_state` 内存缓存；
   重启或首次查看时必须实读网络盘，网络拥塞时直接失败，没有磁盘级兜底。
2. SMB 读取失败后没有重试，也没有“网络异常时先少碰网络”的降级机制；
   连续翻图/预加载会反复触发超时，进一步拖慢页面。
3. Windows 默认开启多媒体网络限流（`NetworkThrottlingIndex`），
   大流量下载时会对 SMB 流量做额外限制，放大超时概率。

### Bug 2

锁定视图原先只维护**一份全局锁定状态**：切换活动面板时，会把当前面板的视图复制到另一侧。
因此「点另一张图」= 切换活动面板 + 复制视图，右侧被迫套用左侧的缩放，出现跳动。

---

## 三、解决方案

### Bug 1：三层容错 + 本地显示缓存 + 系统限流辅助脚本

1. **新增本地显示图磁盘缓存** `image_cache.py`
   - 只缓存主界面用的显示 JPEG（最长边 1920），不缓存原图，不修改共享盘任何文件。
   - 缓存键 = 绝对路径 + mtime + 文件大小：源图更新后自动失效。
   - 原子写入（临时文件 + `os.replace` + `fsync`）。
   - 默认上限 2GB / 60 天，按最久未使用清理；提供 `stats / clear / prune`。
   - 缓存目录：存在 `D:\VelkozDATA` 时用 `D:\VelkozDATA\cache\display`，
     否则用 `%LOCALAPPDATA%\Velkoz\display_cache`；可用环境变量 `VELKOZ_DISPLAY_CACHE` 覆盖。
2. **主界面读取链路改造** `disk_io.get_display_image_bytes`
   - 第 1 层：`session_state` 内存缓存（最快）。
   - 第 2 层：本地磁盘缓存精确命中（路径 + mtime + 大小），命中时**完全不碰网络盘**。
   - 第 3 层：磁盘缓存未命中才读源图，最多 3 次重试（间隔 0.25s / 0.8s）。
   - 全部失败：进入 20 秒“降级模式”，回退最近一次成功缓存；没有缓存则返回占位图并在日志记录。
   - 回退缓存时分辨率文本带「本机缓存」标记，避免把旧图误当成最新图。
   - 降级期间 `preload_next_images()` 直接跳过预取，避免继续制造 SMB 超时。
   - 每写入 200 次自动做一次 LRU/过期清理，缓存不会无限增长。
3. **图片解码容错** `utils._load_and_rotate`
   - `Image.verify()` 失败时不再强行 `Image.open` 抛异常，改为安全返回 `None`，交给上层兜底。
4. **设置页新增缓存面板** `settings_mixin._render_display_cache_section`
   - 显示缓存位置 / 张数 / 占用空间，支持一键清空；并提示限流脚本与百度网盘限速建议。
5. **新增根目录辅助脚本 `修复网络限流.bat`**（需管理员，不自动执行）
   - `NetworkThrottlingIndex = 0xffffffff`（关闭多媒体网络限流）
   - `SystemResponsiveness = 0`（前台程序优先）
   - `SessTimeout = 30`（SMB 会话超时更宽裕）
   - 重启后生效；`修复网络限流.bat restore` 可恢复系统默认。
   - 只改本机注册表，**不写入局域网共享盘**。

### Bug 2：每个面板独立视图 + 独立「同步缩放」开关

1. 锁定状态从「一份全局状态」改为「每个面板各存一份」：
   - `_panel_states = [None, None]`，`state_for_panel(panel)` 只取本面板状态。
   - 切换活动面板（点击另一侧）不再复制缩放，另一侧大小保持不变。
2. 新增工具栏开关 **「🔗 同步缩放」**（`act_sync_zoom`，默认关闭，状态持久化到 `settings.json` 的
   `image_viewer.sync_zoom`）：
   - 关闭：两侧完全独立，缩放/平移只作用于当前侧（默认行为）。
   - 开启：放大、缩小、适应窗口、1:1、右键平移都会同步到另一侧。
3. 状态栏新增「🔗 同步缩放」提示，工具栏与状态栏状态保持一致。
4. 布局切换、图片集刷新时改为 `_capture_all_views()`，两侧各自保存/恢复自己的视图。

## 六、已知限制

1. 首次查看某张图片时仍需从共享盘读取；若此时网络完全不可用且从未缓存过，只能显示占位图。
2. 缓存按「路径 + mtime + 大小」判断版本；若源图被替换但 mtime/大小恰好不变，可能短暂显示旧图。
3. `修复网络限流.bat` 修改本机注册表，需要管理员权限并**重启生效**；部分安全软件可能拦截。
4. 缓存目录建议保留在本机磁盘，否则（如放到网络盘）会失去提速意义。
5. 同步缩放使用“相对 Fit 缩放 + 相对中心点”，两图宽高比差异很大时视觉中心会略有差异，但缩放倍数一致。

---

## 七、迁移与使用

- 直接覆盖升级即可，无需迁移数据。
- 老用户默认「同步缩放」为关闭，行为与需求一致：左右各自独立。
- 需要联动时，点工具栏「🔗 同步缩放」；设置会记住。
- 缓存可在「设置 → 局域网图片显示缓存」查看和清空。
- 网络仍卡顿时，右键管理员运行 `修复网络限流.bat`，重启；或把百度网盘下载限速到带宽 80%。

---

## 八、回滚方案

1. 代码回滚：`git revert <本次提交>` 或 `git checkout v1.24.1`。
2. 仅关闭新行为：
   - 查看器侧：确保 `settings.json → image_viewer.sync_zoom = false`。
   - 缓存侧：清空「局域网图片显示缓存」不会影响源文件；删除缓存目录即可完全停用缓存效果。
3. 注册表恢复：管理员运行 `修复网络限流.bat restore`，重启。
